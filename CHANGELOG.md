### Migration Notes

- **compose/drag**: `DragEvent.x` and `DragEvent.y` now carry the **absolute pointer position**
  within the composable, not the per-event movement delta. If your `GestureConfig.onDrag` lambda
  was accumulating `x`/`y` across events to compute total motion (e.g. `totalX += event.x`), you
  must migrate to `delta.dx` / `delta.dy` — the new `DragDelta?` field on `DragEvent` that
  carries the frame-to-frame movement. `delta` is `null` in `onDragStart` (no prior position to
  diff against) and non-null for all subsequent `onDrag` callbacks. Consumers that were already
  treating `x`/`y` as an absolute screen coordinate require no change.

  **Binary ABI note:** `DragEvent.copy()` gained a third parameter (`delta: DragDelta?`). Any
  code compiled against a previous release that calls `dragEvent.copy(x = newX)` or
  `dragEvent.copy(x, y)` (two `Double` args) will fail at runtime with `NoSuchMethodError`.
  Recompile against this release; no source change is required for named-argument call sites
  (`dragEvent.copy(x = newX)` compiles correctly against the new descriptor).

- **core/rotation — BREAKING**: `rotateX` and `rotateY` now use the right-handed
  counter-clockwise convention. Before this release, positive angles rotated clockwise (an
  inverted convention). After this release, a positive angle rotates counter-clockwise when
  viewed from the positive end of the axis, matching `rotateZ` and the standard mathematical
  convention.

  **Migration:** Negate any angle you pass to `rotateX` or `rotateY` to preserve the old
  visual output:

  ```kotlin
  // Before
  shape.rotateX(origin, angle)
  shape.rotateY(origin, angle)

  // After (to restore old CW visual)
  shape.rotateX(origin, -angle)
  shape.rotateY(origin, -angle)
  ```

  `rotateZ` is unchanged.

- **core/shapes — BREAKING (visual)**: `Octahedron` proportions corrected. Before this
  release, the shape applied a non-uniform post-scale that compressed the X and Y axes to
  ~70.7 % of the Z axis span. After this release, `Octahedron` is inscribed in a unit cube
  with all three axes spanning [0, 1].

  **Migration:** Re-record Paparazzi golden images. No API change is required.

- **core/shapes — BREAKING (visual)**: `Knot` positioning corrected. Before this release,
  `Knot(position)` applied a hardcoded internal translate of (-0.1, 0.15, 0.4) after scaling,
  displacing the shape from the requested `position`. After this release, the shape is
  geometrically centered at `position`.

  **Migration:** Re-record Paparazzi golden images. If you explicitly compensated for the old
  offset by adding a counter-delta to `position`, remove that compensation.

- **compose/tap-timing — BREAKING (behavioral)**: `onClick` is now dispatched with a
  disambiguation delay when the node also has `onDoubleClick`. Before this release, `onClick`
  fired immediately on every Release regardless of whether `onDoubleClick` was present. After
  this release, when both handlers are present, `onClick` is deferred until the platform
  double-tap window (`ViewConfiguration.doubleTapTimeoutMillis`) expires; a confirmed
  double-tap fires `onDoubleClick` and suppresses `onClick` entirely.

  **Migration:** If your node has both `onClick` and `onDoubleClick` and your code relied on
  `onClick` firing immediately (e.g. you expected an instant visual update on first tap),
  evaluate whether the disambiguation delay is acceptable for your use case. If immediate
  `onClick` response is required, remove `onDoubleClick` and implement the double-tap
  detection yourself, or use only `onDoubleClick`. Nodes with only `onClick` (no
  `onDoubleClick`) are also subject to the delay — the scene cannot determine at first-tap time
  whether a second tap is arriving. The scene-level `GestureConfig.onTap` is unaffected and
  fires immediately.
